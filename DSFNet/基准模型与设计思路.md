# 基准模型与设计思路（B0–B6）

## 术语定义（统一）

- 条件化跨注意力（Conditional Cross-Attention）
  - Level 1（简单，B3–B4）：当 vts_valid=0 时跳过跨注意力，直接返回 Q（恒等映射）；vts_valid=1 时正常计算。
  - Level 2（完整，B6）：构造 attn_mask 将缺失模态样本的 K/V 注意力分数置为 -inf，从而在算子级屏蔽。
- 零化（Zero-filling）：缺失模态的特征向量置为 0。
- Presence flag / embedding：
  - presence flag：在拼接/分类前附加一个标量标志位（如 vts_valid∈{0,1}）。
  - presence embedding：当模态缺失时，在特征提取后、融合前用一个可学习的向量（维度=E）替代该模态的全零特征，缓解分布偏移。与 presence flag 的区别：flag 是标量（0/1），embedding 是 E 维特征向量。
- 门控（Gating）：通过 g∈(0,1) 对两模态进行通道级加权融合。

## 通用设置

- 输入与归一化：`[B,1,512,512]`，float32，归一化使用 `stats.json`（train 集计算）
- 数据增强：背景混合、频移、时间拉伸、噪声、保守 SpecAugment
- 训练：AdamW + Cosine + Warmup，AMP，梯度裁剪 1.0，LayerNorm eps=1e-6
- 划分与评估：遵循《模型架构和具体参数.md》第10节（A/B两类划分策略），报告 TKR/TUR/KP/H/OSA，并在 vts_valid 子集分别统计

## B0：FCS-only（单流基线）

- 结构：Swin-Base（单通道改造）→ GAP → LN → FC
- 目标：量化 FCS 单模态的可达上限，作为融合与VTS增益的参照
- 训练要点：
  - 可直接全数据（含 vts_valid=0/1）训练，VTS 信息不参与
  - 关注类间混淆与窗口/输入尺寸对结果的影响

## B1：VTS-only（单流基线）

- 结构：ConvNeXt-Base（单通道改造）→ GAP → LN → FC
- 目标：量化 VTS 单模态的可达上限（在 VTS 可用的样本/类上）
- 训练要点：
  - 仅使用 vts_valid=1 的样本；与 B0 的已知类集合尽量一致，以便对照

## B2：双流简单拼接（无注意力）

- 结构：Swin(F) 与 ConvNeXt(V) 提取 `[B,N,E]`，做 token 维度或 GAP 后拼接 → MLP → 分类
- 目标：评估“无交互、无门控”的早期融合效果
- 缺失处理（明确规范，推荐方案）：
  - 若 vts_valid=0：
    1) 将 V_tokens 先零化（Zero-filling）；
    2) 在 GAP 后，用可学习的 presence_embed ∈ R^E 替代 v_gap（特征提取后、融合前）;
    3) 拼接时附加 vts_valid 的标量标志（presence flag）。
  - 拼接示例：`concat = [f_gap, v_gap_or_embed, vts_valid]`（维度 2E+1）。
  - 说明：仅“零化”可能引入全零聚类，presence_embed 可缓解分布偏移；flag 提供显式告知，避免隐式泄露。
- 训练要点：
  - 归一化与尺度：对拼接向量进行 LayerNorm/BN 可提升稳定性；
  - 类平衡与模态平衡可选，详见主文档采样策略。

## B3：单向 Cross-Attn（F<-V）

- 结构：以 F 作为 Query，V 作为 Key/Value 的单向跨注意力 → F 更新后分类
- 条件化屏蔽（统一定义）：使用 Level 1——vts_valid=0 时跳过交互，返回 Q；vts_valid=1 时正常注意力。
- 训练要点：关注注意力熵/峰度，避免随机噪声主导。

## B4：双向 Bi-Cross-Attn（无门控）

- 结构：F<-V 与 V<-F 两个跨注意力层，输出级联或加权融合 → 分类
- 条件化屏蔽：Level 1（同 B3），确保缺失模态时不传播伪信息。

## B5：Bi-Cross-Attn + 简单门控（DMG_v1）

- 结构：在 B4 基础上加入通道级门控 g（不含尺度提示与温度），`fused = g*F + (1-g)*V`
- 门控输入（明确）：`[f_gap; v_gap]`（拼接后经 MLP → E 通道的 g）。
- 缺失约束：对 vts_valid=0 的样本施加软监督（L_gate，使 g→1），但不做硬性强制。

## B6：Bi/Conditional Cross-Attn + DMG_v2（推荐基线）

- 结构：条件化跨注意力（Level 2，attn_mask），DMG_v2（含 presence flags、尺度提示、温度）+ 多尺度/伪时间时序编码 + 分类头
- 门控输入（完整）：`[f_norm; v_norm; scale_f; scale_v; fcs_valid; vts_valid]` → MLP → g，并含可学习温度 τ 与通道尺度自适应。
- 缺失约束：对 vts_valid=0 采用硬约束 `g = 1`（退化到 F 分支），并辅以轻量正则。
- 核心创新点（与常规 Bi-Attn 的区别）：
  1) Conditional 机制：按样本级屏蔽缺失模态，避免伪特征传播（Level 2 实现）。
  2) DMG_v2 门控：显式模态标志 + 尺度提示 + 可学习温度，防止 gate collapse。
  3) Temporal 建模：融合后接 Temporal Transformer，捕获隐式多普勒时序。

### B5 vs B6 关键差异

| 特性 | B5 (DMG_v1) | B6 (DMG_v2) |
|---|---|---|
| 门控输入 | `[f_gap; v_gap]` (2E) | `[f_norm; v_norm; scale; flags]` (2E+4) |
| 归一化 | 无 | L2归一化 |
| 尺度信息 | 无 | 有（scale_f, scale_v）|
| 模态标志 | 无 | 有（fcs_valid, vts_valid）|
| 温度缩放 | 无 | 有（可学习 τ）|
| 缺失约束 | 软监督（g→1） | 硬约束（g=1）+ 软正则 |
| 通道尺度自适应 | 无 | 有（learnable scale）|
| 稳健性 | 容易 gate collapse | 缺失更稳、分布更分散 |

## 附录A：常见问题与调试清单

### A.1 训练不收敛/Loss 震荡

- 症状：Loss 在前 10 epochs 后仍震荡；Val Acc < 80%
- 排查/修复：
  - 学习率过大 → 降低 LR 或增加 warmup；
  - 增强过强 → 暂停增强 10 epochs 验证；
  - 梯度爆炸 → 降低 clip_norm（1.0→0.5）；
  - 门控损失冲突 → 延后 gate loss（epoch 10+）；
  - 冻结过度 → 解冻更多层或提高 backbone_lr。

### A.2 Gate Collapse（门控崩塌）

- 症状：`g_with_vts` 与 `g_without_vts` 都接近 0.5/1.0；`std(g) < 0.05`
- 处理：增大 τ 初值（2.0+）、降低缺失监督 α、检查 VTS 数据与 batch vts_ratio。

### A.3 VTS 缺失时性能骤降

- 症状：`vts=0` 子集 TKR 远低于 `vts=1`（>10%）
- 处理：校验 Conditional Attn（Level1/2）、启用 `g→1` 约束、检查 FCS 基线、提升 VTS 样本占比或分层采样。

### A.4 开放集性能差（TUR 低）

- 症状：TUR < 85%
- 处理：降低阈值（p95→p90）、增大 center EMA（0.9→0.95）、更换未知类、更高 CenterLoss 权重（0.005→0.01）。

### A.5 复现失败（不同 run 差异大）

- 检查清单：`set_seed()`、`worker_init_fn`、`generator.manual_seed()`、`cudnn.deterministic/benchmark`、DataLoader shuffle、一致的异步设置。

### A.6 显存不足（OOM）

- 优先级：降低 batch_size + 累积梯度 → 降输入 → 启用 grad checkpoint → 降 worker → 关闭重型可视化。

### A.7 训练速度慢

- 优化：AMP、部署时关闭 deterministic、增 workers、pin_memory、精简增强、监控 GPU 利用率。

- 预期速度（示例，RTX 5080 16GB, batch=16）：B0≈2 min/epoch；B6≈4 min/epoch。

#### 阶段4：当前已知问题 — wh回归输出过小

**症状**（VTS HeadOutUp=4, H=128×128训练）:
- ✅ hm_max=0.47（热图学习正常）
- ✅ total_decoded_boxes=140（解码成功）
- ❌ **框宽高仅1-3px**（vs 预期8-50px），IoU≈0

**根本原因分析**：
- wh头使用**绝对栅格单位**回归：`wh_gt = w_norm * W`（W=64或128）
- HeadOutUp从2→4时，W从64→128翻倍，**要求wh值也翻倍**
- 但线性sigmoid回归难以适应分辨率变化，导致输出值严重偏小（wh_range=[0.009, 0.156] in feature coords）

**待实施修复方案**：
1. **wh参数化改进**：
   - 当前：`wh_pred = sigmoid(raw_wh) * W`
   - 改为：`wh_pred = softplus(raw_wh)`，loss用log空间：`L1(log(pred+ε), log(gt+ε))`
   - 优势：解耦分辨率，回归log(wh)在[0,∞)更稳定
2. **解码时归一化**：
   - 训练监督在[0,1]归一化空间
   - 解码时乘W/H得像素坐标
3. **Per-class NMS**：按类别分别NMS，避免类间框干扰

### CUDA崩溃排查

**已完成修复**:
- PS1脚本变量引用: `${StemMin}-${StemMax}` 避免解析错误
- mAP计算移到CPU: `train_b0_det.py` Line 683/731 添加 `.detach().cpu()`，避免异步CUDA错误
- 默认参数优化: `SMNetPreproc/UsePFAware/PFAwareLite` 改为 `$false` 默认
- **UTF-8 BOM问题**: PS1的 `Set-Content -Encoding UTF8` 会添加BOM，导致路径解析错误 `\ufeffC:\...`
  - 修复: 改为 `[System.IO.File]::WriteAllLines` with `UTF8Encoding($false)`
  - PowerShell 5.1 不支持 `utf8NoBOM` 参数，需用 .NET 方法
- **GPU batched_nms 兼容性问题** (2025-10-24 19:00):
  - **症状**: 训练第一个batch前向传播后,调用 `_decode_predictions` 时立即崩溃在 `c10::cuda::CUDAEvent::record`
  - **根因**: `torchvision.ops.batched_nms` 在GPU上执行时,Windows+4060环境下触发异步CUDA错误
  - **修复**: `_decode_predictions` 输出统一改为CPU设备:
    - 直接在CPU构造张量: `torch.tensor(..., device='cpu')`
    - NMS在CPU执行: 无需GPU→CPU转换
    - 空框也输出CPU张量: `torch.zeros((0,4), dtype=torch.float32)`
  - **影响**: 解码性能略降（~10ms/batch），但完全避免CUDA崩溃
- **设备混用问题** (2025-10-24 19:20):
  - **症状**: `_compute_detection_metrics` 中 `_box_iou` 报错 "found at least two devices, cuda:0 and cpu"
  - **根因**: `_targets_to_metric_fmt` 使用外部 `device` 变量构造GPU张量,与 `_decode_predictions` 返回的CPU张量混用
  - **修复**: 
    - `_targets_to_metric_fmt` 强制在CPU: `t_cpu = t.cpu() if t.is_cuda else t`
    - 移除 `device=device` 参数,用 `torch.zeros_like(boxes)` 自动继承CPU设备
    - 确保所有输出都在CPU: dets/tgts/metrics 完全在CPU计算
